# PitchLog 1차 기획·설계 발표 — 슬라이드별 변경 요약

## 2026-09-02 백엔드 구조 변경

- Spring Boot Core + Redis Pub/Sub + 별도 Node.js Gateway 구조를 폐기했습니다.
- NestJS + TypeScript + PostgreSQL + Prisma 통합 백엔드로 변경했습니다.
- 초기에는 REST, 데이터 수집, Scheduler, Socket.io를 하나의 애플리케이션에서 운영합니다.
- 대량 작업이 필요할 때만 Redis + BullMQ Worker를 추가합니다.
- 발표 슬라이드 13·14·16과 발표자 노트를 새 구조에 맞게 수정했습니다.
- 최신 발표본: `PitchLog_1차_기획설계_발표_v5.pptx`

## 전체 변경 방향

- 발표 성격을 **개발 완료·기술 보고**에서 **1차 기획·설계 발표**로 전환했습니다.
- PitchLog의 범위를 EPL 전용이 아닌 **유럽 5대 리그 + UEFA Champions League 데이터 플랫폼**으로 명확히 했습니다.
- EPL 2026–27은 전체 구조를 검증하는 **첫 구현 범위**, 5대 리그 + UCL은 **확정된 최종 범위**로 구분했습니다.
- 클래스, Repository, DTO, 상세 엔드포인트, 라이브러리 버전, 배포 세부값 등 초급 발표에 과한 구현 정보는 본문에서 제외했습니다.
- 실제 구현 화면을 넣을 수 있도록 7–11장에 큰 편집형 화면 삽입 영역을 배치했습니다. 생성형 고품질 이미지는 사용하지 않았습니다.
- AI는 현재 구현처럼 보이지 않도록 **Phase 5 계획**으로만 배치하고, 13장에는 의도적으로 단순한 편집형 와이어프레임을 사용했습니다.

## 슬라이드별 Before → After

| 새 슬라이드 | 원본 내용 | 변경 후 | 변경 이유 |
|---|---|---|---|
| 1 | EPL 중심 프로젝트 표지 | `PitchLog — 유럽 클럽축구 데이터 플랫폼` 표지 | 서비스의 최종 범위와 발표 성격을 첫 화면에서 명확히 전달 |
| 2 | 프로젝트 개요와 규모 수치 | 축구 정보 탐색에서 사용자가 겪는 네 가지 문제 | 기능·기술보다 기획의 출발점인 사용자 문제를 먼저 제시 |
| 3 | 기술 스택 소개 | 서비스 목표와 `다중 대회·실시간성·신뢰성·확장성` 설계 원칙 | 이후 화면과 기능을 평가할 공통 기준 제시 |
| 4 | 도메인 모델과 데이터 구조 | EPL 첫 구현 범위와 5대 리그 + UCL 최종 범위 비교 | EPL 전용 서비스라는 오해를 방지하고 단계적 구현 논리를 설명 |
| 5 | 백엔드 아키텍처 | `경기 탐색·통계 확인·LIVE/AI`의 세 사용자 경험 | 서버 구성 대신 사용자가 실제로 할 수 있는 일을 중심으로 재분류 |
| 6 | Node 게이트웨이 구조 | 전체 화면 구조와 세 가지 대표 사용자 흐름 | 내부 호출 구조를 사용자의 탐색 흐름으로 변환 |
| 7 | AI 아키텍처 | 홈 실제 구현 화면 삽입 영역과 확인 포인트 | 핵심 UI를 크게 보여 주고, AI 설명은 Phase 5 슬라이드로 이동 |
| 8 | 배포 전략 | 대회 상세·순위 실제 구현 화면 삽입 영역 | 기술 운영 정보보다 대회·시즌 맥락이 유지되는 UX를 설명 |
| 9 | 기능·데이터 흐름 | 팀 상세·전체 일정 실제 구현 화면 삽입 영역 | 국내 리그와 UCL 일정을 한 팀 기준으로 확인하는 핵심 문제를 시각화 |
| 10 | 사이트 경로 목록 | 선수 상세 실제 구현 화면 삽입 영역 | URL 나열은 6장의 구조도로 단순화하고, 사용자가 보는 통계 화면을 강조 |
| 11 | 작은 화면 자리표시자 모음 | 경기 상세·UCL 녹아웃 실제 구현 화면 삽입 영역 | 한 장에 여러 작은 시안을 넣는 대신 주요 화면을 한 장씩 크게 설명 |
| 12 | 개발 로드맵 | `LIVE → FINAL → RECHECK` 데이터 갱신·신뢰 흐름 | 실시간 속도와 종료 후 확정 데이터의 차이를 초급자도 이해하도록 단순화 |
| 13 | 엔지니어링 원칙 | Phase 5 AI 역할 경계와 단순 채팅 와이어프레임 | AI가 숫자를 만들지 않고 검증된 데이터를 설명한다는 책임 범위를 명확화 |
| 14 | Q&A | Phase 0–5 로드맵과 세 가지 최종 메시지 | 발표를 질문 화면으로 끝내지 않고 구현 순서와 기획 결론으로 마무리 |
