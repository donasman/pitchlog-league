# 홈 / 경기 탭 재구성 검토 (2026-09-03)

> 발단: "지금 홈 화면을 경기 탭으로 옮기고, 홈이 하나 새로 필요할 것 같다"
> 결론부터: **맞는 판단이다. 다만 옮기고 나면 홈에 남는 게 거의 없어서, 새 홈은
> 덜어내서 만드는 게 아니라 새로 정의해야 한다.**

---

## 1. 근거 — 홈 요소 7개 중 5개가 경기 탭과 중복

현재 `/`(HomePage)의 구성 요소를 `/matches`(MatchesPage)와 대조했다.

| # | 홈 요소 | `/matches`에 있는가 | 판정 |
|---|---|---|---|
| 1 | 대회 필터 칩 | `FilterBar` 대회 필터로 존재 | **중복** |
| 2 | 요약 스트립 (진행중·오늘·선두·득점1위) | 없음 | 고유 |
| 3 | LIVE 히어로 카드 | LIVE 섹션으로 존재 (형태만 다름) | **중복** |
| 4 | 보조 경기 카드 2건 | LIVE·예정 섹션에 포함 | **중복** |
| 5 | 오늘의 경기 8행 | 예정+LIVE의 부분집합 | **중복** |
| 6 | 사이드바 — 순위 Top5·득점 Top5·UCL 진출 | 없음 | 고유 |
| 7 | 하단 3열 — 최근 결과·다음 경기·UCL 16강 | 종료+예정 섹션 | **중복** |

**7개 중 5개가 중복이다.** 게다가 중복된 쪽이 홈이 더 낫다 —
홈은 히어로 카드가 있고 "오늘"이라는 시간 축이 있는데,
`/matches`는 `max-w-4xl` 좁은 폭에 필터 두 개와 목록뿐이다.

즉 **지금 구조는 경기 화면이 두 개고, 못 만든 쪽이 탭을 차지하고 있다.**

## 2. 옮기면 홈에 무엇이 남는가

중복 5개를 `/matches`로 옮기면 홈에 남는 것:

- 요약 스트립 4칸
- 순위 Top5
- 득점 Top5
- UCL 녹아웃 진출 팀

**요약 블록 4개다. 화면 하나로 세우기엔 약하다.**
그리고 이 넷은 각각 `/standings`, `/stats`, UCL 녹아웃의 축약본이라,
"어디로 갈지 고르는 링크 모음" 이상이 되기 어렵다.

→ 그래서 새 홈은 **남은 것으로 만들면 안 된다.** 새 역할을 줘야 한다.

## 3. 참고 — 경쟁 서비스는 홈과 경기를 나누지 않는다

FotMob, FlashScore, Sofascore 모두 **홈 = 오늘 경기**이고 경기 탭이 따로 없다.
나누면 둘 중 하나가 반드시 약해지기 때문이다. 실제로 지금 우리가 그 상태다.

따라서 선택지는 셋이다.

---

## 4. 선택지 3안

### A안 — 홈을 없앤다 (`/` → `/matches`)

탭이 **경기 · 대회 · 순위 · 팀 · 통계** 5개가 된다. 로고를 누르면 경기로 간다.

- **장점** — 업계 표준과 같다. 중복이 완전히 사라진다. 만들 화면이 줄어든다.
- **단점** — 사용자가 "홈이 필요하다"고 느낀 지점을 해소하지 못한다.
  서비스 전체를 조망하는 자리가 없어진다.

### B안 — 홈 = 6개 대회 개관

각 대회 카드에 현재 라운드, 진행 중 경기 수, 선두 팀, 득점 1위.
"오늘 어느 대회가 도는가"를 고르는 화면.

- **장점** — 6개 대회를 다룬다는 이 서비스의 성격이 첫 화면에 드러난다.
  경기 탭과 역할이 완전히 갈린다.
- **단점** — **`/competitions`와 정면으로 겹친다.** 이 안을 택하면
  `/competitions`를 없애고 홈이 그 역할을 흡수해야 한다.
  그러면 탭이 **홈 · 경기 · 순위 · 팀 · 통계** 5개로 깔끔해진다.

### C안 — 홈 = 개인화 (관심 팀·대회 중심)  ★ 추천

사용자가 고른 팀과 대회만 보여준다. 로그인 없이 브라우저에 저장한다.

```
내 팀의 다음 경기 / 최근 결과
내 팀이 속한 순위표 구간 (앞뒤 2팀)
내가 고른 대회의 오늘 경기
관심 선수 기록
```

첫 방문이면 EPL 기본값으로 채우고, 상단에 "관심 팀 고르기"를 둔다.

- **장점** — 경기 탭(전체)과 역할이 명확히 갈린다. **홈은 좁고 깊게, 경기는 넓고 얕게.**
  "우리 팀 어떻게 됐지"(동선 B)의 진입 비용이 사라진다.
  로그인 없이 구현 가능하고, 포트폴리오에서 설명할 거리가 된다.
- **단점** — 첫 방문자에게는 기본값 화면이라 개인화가 안 느껴진다.
  브라우저를 바꾸면 초기화된다.

---

## 5. 추천 — C안, 조건 하나 붙여서

**C안(개인화 홈)을 권한다.** 이유는 역할 분리가 가장 선명하기 때문이다.

| 탭 | 역할 | 성격 |
|---|---|---|
| **홈** | 내가 고른 것만 | 좁고 깊게 |
| **경기** | 전체 경기 + 필터 | 넓고 얕게 |
| 대회 | 대회별 허브 | 대회 단위 |
| 순위 | 순위표 | 데이터 |
| 팀 · 통계 | 각 데이터 | 데이터 |

이렇게 하면 어느 탭도 다른 탭의 약한 버전이 아니다.

**붙일 조건:** 첫 방문자 화면을 반드시 설계한다.
관심 팀이 없을 때 홈이 비어 보이면 A안보다 나쁘다.
기본값(EPL)으로 채우되, **"관심 팀을 고르면 이 화면이 당신 것이 된다"** 를
한 줄로 알려주는 자리를 둔다.

**B안도 나쁘지 않다.** 구현이 더 쉽고 `/competitions`를 흡수하면 구조가 깔끔해진다.
개인화가 부담스러우면 B안으로 간다.

**A안은 지금 단계에서 권하지 않는다.** 중복은 없어지지만
"6개 대회를 다루는 서비스"라는 성격이 첫 화면에서 사라진다.

## 6. 어느 안을 고르든 함께 정할 것

| # | 항목 | 내용 |
|---|---|---|
| 1 | **`/matches`를 다시 만든다** | 지금은 좁은 폭에 필터 두 개뿐이다. 홈에서 옮겨오는 히어로 카드·오늘 축·날짜 그룹핑을 받아야 제대로 된 경기 허브가 된다 |
| 2 | **`/competitions` 처리** | B안이면 흡수해 삭제. A·C안이면 유지하되 홈과 역할이 겹치지 않는지 재확인 |
| 3 | **탭 6개 → 5개** | 현재 홈·대회·경기·팀·순위·통계 6개는 모바일에서 많다. 5개로 줄이는 게 좋다 |
| 4 | **디자인 브리프 갱신** | `docs/design-briefs/03-home.md`가 현재 홈 구성을 전제한다. 결정 후 03과 05를 다시 쓴다 |
| 5 | **PRD 6-1 갱신** | 홈 화면 명세가 바뀐다 |

---

## 7. 결정 후 작업 순서

```
1. 안 선택 (A / B / C)
2. PRD 6-1 홈 명세 재작성 + 6-3 경기 목록 명세 보강
3. design-briefs 03(홈)·05(경기) 재작성
4. 디자인 → 구현
```

**디자인 브리프를 Claude Design에 넣기 전에 이걸 정해야 한다.**
3단계(홈)를 그린 뒤에 바꾸면 그 작업이 버려진다.
