## 0. 데이터를 나누는 축

수집 기능은 **"얼마나 자주 변하는가"** 가 아니라
**"실패하면 무슨 일이 일어나는가"** 로 나눈다 (V2_DESIGN 5-3).

| 계층 | 변경 빈도 | 실패했을 때 | 실행 방식 |
|---|---|---|---|
| **L0 기준 데이터** | 시즌당 1회 | 아무것도 안 됨 | Job (수동/시즌 초) |
| **L1 명단·소속** | 주 1회 ~ 일 1회 | 명단이 낡음 (사이트는 돎) | Job |
| **L2 일정** | 라운드 확정 시 | 일정이 틀림 | Scheduler |
| **L3 경기 직전** | 킥오프 1시간 전 | 라인업 없음 (사이트는 돎) | Scheduler |
| **L4 실시간** | 10~15초 | **틀린 스코어를 보여줌** | Scheduler |
| **L5 종료 후 확정** | 경기당 1회 | **틀린 순위·통계를 보여줌** | Scheduler + 재시도 |
| **L6 보정** | 일 1회 / 주 1회 | 누락이 안 고쳐짐 | Job |

**L4·L5가 실패하면 사이트가 거짓을 말한다.** 이 둘만 실패를 화면에 노출한다 (회고 4-6).
나머지는 다음 주기에 복구되면 된다.

## 1. 수집 기능 (ingestion)

### L0 — 기준 데이터 · 시즌당 1회

가장 먼저 채워야 하고, 이게 없으면 나머지 전부 FK를 걸 곳이 없다.

| # | 기능 | API | 콜 수 | 멱등 키 |
|---|---|---|---|---|
| 1 | 대회 등록 | `/leagues?id=` | 6 | `api_competition_id` |
| 2 | 시즌 등록·대회별 현재 시즌 판정 | `/leagues` 응답의 seasons | 위에 포함 | `(competition_id, season_id)` |

**#8 스쿼드 diff — 이 계층의 전부**

API는 현재 스냅샷만 준다. 이력을 만들어내는 건 우리 몫이다.

```
직전 스냅샷과 비교
├─ 사라진 선수  → left_at = 수집일, (해당 row 종료)
├─ 새로 나타남  → 신규 row (joined_at = 수집일)
├─ 등번호 변경  → 기존 row 갱신
└─ 변화 없음    → no-op
```

- ⚠ `joined_at`/`left_at`은 **수집일이지 실제 이적일이 아니다.** 최대 7일 오차.
  따라서 **경기의 팀 귀속을 이 값으로 판단하면 안 된다** (검토 A-2).
- ⚠ 임대/완전이적 구분 불가. `transfer_type`은 `UNKNOWN`으로 시작 (검토 A-4).
- 이적창(6/13~9/1, 1/1~2/3)에는 주기를 일 1회로 올린다. **마감일엔 수십 건이 몰린다.**

## 2. 조회 API (read)

프론트 `services/api.js`의 함수에서 역산했다. **화면이 요구하는 것이 곧 계약이다.**

| 엔드포인트 | 화면 | 비고 |

- 오류를 빈 배열로 바꾸지 않는다. 실패는 실패로 응답한다.

### 3-1. 푸시 알림 (2026-09-03 범위 추가)

인앱 전달(40~47)과 달리, 브라우저가 닫혀 있어도 기기로 보낸다. **신규 작업이다.**

| # | 기능 | 비고 |
|---|---|---|
| 47-1 | VAPID 키 발급·보관 | 환경변수. 재발급하면 기존 구독이 전부 무효 |
| 47-2 | 구독 등록·해지 API | endpoint · p256dh · auth 저장 |
| 47-3 | 구독별 관심사 저장 | 팀 · 대회 · 이벤트 종류. **`owner_key` 컬럼을 함께 둔다** — 로그인 도입 시 user_id를 연결할 자리 (PRD 8-1) |
| 47-4 | 발송 대상 조회 | 이벤트 → 그걸 원하는 구독 목록 |
| 47-5 | Web Push 발송 | 같은 경기 알림은 `tag`로 교체 |

L5(#28·#34)에서 트리거한다. 별도 스케줄러를 두지 않는다.

⚠ **로그인이 없는데 사용자별 레코드가 생긴다.** 계정은 아니지만 브라우저 단위 식별자이고
관심 팀이 함께 저장되므로, 보관 기간과 삭제 경로를 정해야 한다.
만료 구독 정리(47-6)가 그 역할을 겸한다.

⚠ **DB 커밋 이후에만 발송한다.** 인앱과 같은 규칙이다. 푸시는 취소가 불가능하므로
잘못 보내면 되돌릴 수 없다.
