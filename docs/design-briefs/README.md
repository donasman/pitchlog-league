# 디자인 브리프 — Claude Design용 단계별 입력

`docs/PRD.md`를 Claude Design에 바로 붙여넣을 수 있는 단위로 쪼갠 것이다.
PRD 전체(366줄)를 한 번에 넣으면 13개 화면을 동시에 고려하느라 어느 것도 깊이 나오지 않는다.

## 순서

| # | 파일 | 내용 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | `01-foundation.md` | 색·타이포·간격 토큰, 경기 상태 배지 8종, 화면 상태 4종, 순위 구역 표기 | 나머지 전부가 여기서 나온다 |
| 2 | `02-components.md` | 헤더, 대회 선택기, 경기 카드, 순위표 행, 필터 바 | **5개 이상 화면에서 반복된다.** 여기서 시간을 쓰면 나머지가 빨라진다 |
| 3 | `03-home.md` | 홈 — **제품 앞장** (데이터 화면 아님) | 사이트의 얼굴. 경기 탭과 겹치면 실패 |

| 7 | `07-notifications.md` | 알림 — 인앱 토스트 · 벨 · 설정 · 푸시 권한 | 신규 범위. Socket.io(Phase 2) 이후 |
| 8 | `08-assistant.md` | AI 어시스턴트 패널 | Phase 5. 자리는 미리 잡는다 |

## 쓰는 법

각 파일은 **자체 완결**이다. 공통 전제(브랜드 컬러, 표면 색, 파랑 분리 규칙, 접근성)가
모든 파일에 반복해 들어있으므로, 필요한 단계 파일 하나만 통째로 붙여넣으면 된다.

**2단계를 건너뛰지 않는다.** 경기 카드와 순위표 행이 확정되기 전에 화면으로 넘어가면
나중에 전부 다시 손대게 된다.

## 현재 구현과의 관계

**디자인이 기준이다.** 이 브리프들은 요구사항(`docs/PRD.md`)에서 나온 것이지
현재 프론트엔드 구현을 옮겨 적은 것이 아니다. 디자인이 확정되면 프론트엔드는
그에 맞춰 전면 교체한다.

따라서 Claude Design은 현재 화면 구조에 얽매이지 않아도 된다.
브리프에 적힌 블록 구성은 출발점일 뿐이고, 더 나은 배치가 있으면 그쪽을 택한다.
지켜야 하는 것은 **각 브리프의 "⚠ 절대 규칙"과 접근성 기준**뿐이다.

(참고로 현재 `frontend`의 Tailwind `--primary`는 초록이고 브리프는 블루 확정값을 쓴다.
교체 시 함께 정리될 부분이라 지금 맞출 필요는 없다.)
