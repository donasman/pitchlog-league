# 데이터 규칙 — 판단과 결정

> `API_FIELDS.md`(2026-09-03 1차 조사)를 승계한다. 그 문서의 **실측 데이터는 생성 문서로 넘기고,
> 사람이 내린 판단과 결정만 여기 남긴다.**

## 이 문서의 위치

| 구분 | 파일 | 누가 쓰나 |
|---|---|---|
| **사실** | `API_INVENTORY.md` · `API_FIELDS_FULL.md` · `CUPS_INVENTORY.md` | 스크립트가 덮어쓴다. 손으로 고치지 않는다 |
| **판단** | **이 문서** | 사람이 쓴다. 스크립트가 건드리지 않는다 |
| 기계용 | `api-inventory.json` · `api-cups.json` | 스크립트가 덮어쓴다 |

재생성:

```bash
API_FOOTBALL_KEY=키 node scripts/probe-api-inventory.mjs   # 약 140콜
API_FOOTBALL_KEY=키 node scripts/probe-cups.mjs            # 약 60콜
```

## 1. 소스 규칙

### 1-1. 한 지표는 한 소스에서만 가져온다

같은 지표를 두 소스가 주면 값이 어긋난다. 필드 단위로 소스를 못 박는다.

| 지표 | 소스 |
|---|---|
| 경기 · 순위 · 라인업 · 선수 기본 통계 | API-Football |
| 팀 xG · goals_prevented | API-Football |
| 선수 xG · xA | (도입 시) 2차 소스 |

### 1-2. 지금은 단일 소스, 구조는 열어둔다

검토 결과 (2026-09-03):

| 제공자 | 판정 |
|---|---|
| Opta (Stats Perform) | ❌ 기업 전용. 공개 가격 없음 |
| StatsBomb Open Data | △ 과거 시즌만. 별도 실험용 |
| Understat | △ 공식 API 없음 — 스크래핑 위험 |
| FBref | ❌ API 없음, 스크래핑 차단 |
| **Sportmonks** | **○ 2차 소스 도입 시 1순위 (유료)** |
| football-data.org | ❌ xG 없음 |

**실제 비용은 ID 매핑이다.** 소스마다 식별자가 다르고, 승강제가 있으면 매년 손봐야 한다.

### 1-3. `external_ids` 테이블을 지금 만든다

```
external_ids(
  id, entity_type,   -- TEAM | PLAYER | COMPETITION
  entity_id FK,
  source,            -- API_FOOTBALL | SPORTMONKS | ...
  external_id,
  UNIQUE(source, entity_type, external_id)
)
```

지금은 `source`에 `API_FOOTBALL` 하나뿐이라 비용이 사실상 0인데,
2차 소스를 붙일 때 마이그레이션이 아니라 행 추가로 끝난다.

### 1-4. 2차 소스 도입 판단 시점

Phase 2 완료 후. 그때 다음이 전부 참이면 도입한다.

- 선수 단위 xG·xA가 화면에서 실제로 필요하다고 판단됨
- 1차 소스 수집이 안정적으로 돌고 있음
- `external_ids` 매핑을 채울 여력이 있음

**1차 소스로 도메인을 세운 뒤 2차를 얹는다.** 백엔드 코드가 0줄인 상태에서
다중 소스부터 설계하면 둘 다 끝나지 않는다.

## 3. 값의 세 가지 상태 ★

숫자가 비어 있는 이유가 **셋**이고 화면에서 다르게 보여야 한다.

| 상태 | 뜻 | 저장 | 화면 |
|---|---|---|---|
| `0` | 발생하지 않았다 | `0` | `0` |
| `null` | 측정되지 않았다 | `null` | `-` |
| **미제공** | 그 대회·라운드에 데이터 자체가 없다 | 결손 플래그 | "이 경기는 통계가 제공되지 않습니다" |

세 번째는 컵 때문에 생겼다. FA컵 예선 라운드는 통계가 **아예 없다**(실측: 이벤트 0·라인업 0·통계 0).
이걸 `null`로 저장하면 "측정 안 됨"과 구분이 안 되고, 매 수집마다 API를 다시 때린다.

### 3-1. null → 0 으로 정규화할 것

카드 · 오프사이드 · 슈팅 · 파울 · 태클 · 듀얼 · 드리블 · 페널티

발생하지 않았다는 뜻이다. 그대로 두면 합계 계산이 깨진다.

### 3-2. null 을 유지할 것

| 필드 | 이유 |
|---|---|
| `rating` | **평점 0점과 평점 없음은 다르다.** 0으로 바꾸면 정렬에서 최하위로 올라온다 |
| `expected_goals` · `goals_prevented` | 측정되지 않았을 수 있다 |
| `position` · `number` | 값이 없는 것 |
| 순위표 `description` · `status` | 구역 설명이 없는 대회가 있다 |

실제로 `null`이 관측된 필드 전량은 `API_FIELDS_FULL.md`의
"null 로 온 필드" 절에 엔드포인트별로 있다. 정규화 계층은 그 목록을 기준으로 짠다.

### 3-3. 정규화 계층은 2단계 착수 전에 넣는다

`services/api.js`에 정규화가 없어 `matchStats.js`·`lineups.js`의 `null`이
경기 상세·선수 상세로 그대로 간다. 화면이 늘어난 뒤 넣으면 전부 고쳐야 한다.

## 5. 컵 대회 규칙 (2026-09-04 조사 반영)

### 5-1. 라운드마다 데이터가 다르다

대회 단위 커버리지 플래그는 **하나**인데 실제 데이터는 라운드마다 갈린다.

| 대회 | 초반 라운드 | 후반 라운드 |
|---|---|---|
| League Cup · DFB Pokal | 완전 | 완전 |
| Coppa Italia · Coupe de France | 이벤트·라인업만 | 완전 |
| Copa del Rey | 이벤트만 | 완전 |
| FA Cup | **전무** | 완전 |

참가 팀이 전부 프로인 대회(League Cup · DFB Pokal)는 예선전부터 완전하다.
아마추어가 들어오는 대회는 그 라운드가 비어 있다.

### 5-2. 라운드 컷오프로 수집한다

프로 팀이 진입하는 라운드부터 경기 상세를 수집한다.
그 이전 라운드는 **경기 목록만** 받는다 (대회당 1콜이라 사실상 공짜).

FA컵 전량 수집은 5년 기준 약 15,000콜을 통계 0인 아마추어 경기에 쓴다.

### 5-3. 컵은 순위표가 없다

전 컵 공통으로 `standings`가 `false`다. 정상이다.
대회 화면이 리그와 구조가 달라야 하고, 대진표(`knockout_ties` + `win_reason`)가 필요하다.

---

## 6. 커버리지 플래그를 수집 조건으로 쓰지 않는다 ★

시즌 초에는 플래그가 전부 `false`였다가 나중에 켜진다.
2026-09-04 실측에서 FA컵 2026 시즌은 등록만 되고 플래그가 전부 `false`였는데,
같은 대회 2025 시즌은 전부 `true`였다.

플래그로 수집 여부를 정하면 **시즌 초에 아무것도 안 받는다.**
플래그는 참고만 하고, 실제 응답 유무로 판단한다.

또한 대회마다 시즌 등록 시점이 다르다 — 2026-09-04 기준
Copa del Rey·Coupe de France는 2026 시즌이 아직 없다.
`competition_seasons.status`(UPCOMING / IN_PROGRESS / FINISHED)가 이래서 필요하다.

## 7. 화면 설계에 주는 영향

| 화면 | 넣을 수 있는 것 | 못 넣는 것 |
|---|---|---|
| 경기 상세 · 통계 탭 | xG · goals_prevented 포함 18개 전체 | — |
| 선수 상세 | 평점 · 키패스 · 듀얼 승률 · 드리블 성공률 · 인터셉트 | 선수 xG |
| 통계 랭킹 | 득점 · 도움 · 카드 · 평점 | xG 랭킹 |
| 팀 상세 | 경기별 xG 추이 · 포메이션별 출전 횟수 | — |
| 컵 경기 상세 | 라운드에 따라 다름 | 하위 라운드는 통계 탭 자체가 없음 |

경기 상세에서 "슈팅 7개, xG 0.33"을 나란히 보여주면
"많이 쐈지만 좋은 기회는 아니었다"가 읽힌다 — 일반 사이트에 흔치 않다.

컵 경기 상세는 **통계 탭이 비는 것이 정상 상태**다. 오류와 구분해 보여준다 (3장 세 번째 상태).
